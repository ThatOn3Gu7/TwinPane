Persistent operation history (unreleased v0.10.0): verification log
(2026-10-27T05:20Z, go1.27.3 linux/amd64)

The change adds `internal/history` (a versioned, atomic JSON store in the
configuration directory), records every background and foreground file
operation, adds the history view to the Tasks screen (`t` then `h`) and a
`historySessions` preference (default 20). File operations, their progress,
notifications and the existing Tasks screen behaviour are unchanged.
Everything below ran in this sandbox (Linux x86_64, Debian 13).

## Summary
- gofmt: clean (`gofmt -l .` printed nothing).
- `go vet ./...`: ok.
- `go test -count=1 ./...`: ok, all packages (22 with tests, 2 without);
  `internal/ui` 109.6 s, `internal/history` 0.43 s, `internal/settings` 0.01 s.
- `go test -race -count=1 ./internal/ui`: ok (115.0 s);
  `-race ./internal/history ./internal/settings`: ok (2.4 s / 1.0 s).
- New tests: `internal/history/history_test.go` (22 tests) and
  `internal/ui/history_test.go` (18 tests), plus one settings test and updated

  (unchanged behaviour, new fixture paths).

## What the new tests cover
- `internal/history`: config-directory path, record/reload round trip with
  times and counts, newest-operation-first and newest-session-first ordering,
  the 20-session default and clamping, retention pruning, the running session
  never pruned even when the limit shrinks to 1, failure/cancel statuses,
  interrupted records (status, no finish time, no duration, explanatory
  detail, stable across reloads), damaged files (kept as
  `history.json.corrupt-<timestamp>`, fresh history usable, reported once),
  empty/truncated files, newer-format files (read-only, byte-identical file
  afterwards), unknown statuses and homeless entries in a hand-edited file,
  40 concurrent start/finish pairs from goroutines, two stores sharing one
  file (sessions merged, no duplicates), private permissions (0600 file, 0700
  folder), bounded file size and clipped UTF-8-safe strings, the per-session
  cap keeping running records, nil-store safety, a failing write reported but
  not fatal, `Update` while running, and `SessionSummary` wording.
- `internal/ui`: a copy is recorded with op/status/dest/sources/counts/times
  and is on disk immediately; move + trash-delete in one run (newest first,
  trash result); failure, cancel and still-running records; an operation that
  TwinPane never saw finish is INTERRUPTED in the next run and shows
  "outcome is unknown"; foreground rename, new file and new folder; a failed
  rename recorded as failed; compress, extract (including a refused unsafe
  entry) and a canceled compress recorded as partial/failed, never success;
  bulk rename partial result; permission change; rclone exit code
  (`rclone exit code 9`); history surviving two restarts with runs newest
  first and the run's records intact; retention read from `settings.json`;
  `+`/`-` changing and saving the limit while never pruning the running
  session; browsing (selection, old/new runs, detail scrolling, back to live
  tasks, close), a 40x12 terminal (no line wider than the screen, keys still
  work), a damaged file keeping recording and warning in the status line, and
  a newer file never overwritten; 200 progress updates adding no extra
  records.

## Real binary on a raw pty (`scripts/ptyterm.py`, 96x24 and 44x18)
- Copied a file between panels (`Copied 1 file`), then `t`, `h`: header
  `Operation history · 1 run · 1 operation · keeping 20`, the run row, the
  operation row `05:03:47 DONE Copy → /tmp/tph2/home/dst` and details with
  state, started time, duration (2.058 s), From/To, Items, `Result: 1 file, 6 B`
  and the summary.
- `-` twice: header and status line changed to `keeping 18` and
  `History keeps the last 18 runs`; `settings.json` afterwards contains
  `"historySessions": 18`.
- Restart: the view shows `2 runs · 1 operation · keeping 18`, lists the new
  (empty) run and the previous one newest first and opens on the run that has
  operations, with its details intact.
- `[` selected the older run; a conflict dialog cancelled with `Esc` stored
  `canceled` with "Canceled safely; remaining items were not processed".
- 44x18: the whole view stays inside the terminal (long rows truncated with
  `…`, footer reduced to `h/Esc … ↑↓ operation`), no wrapping or crash.
- Kill during an operation: a copy blocked on a conflict dialog was killed
  with `kill -9` (the record on disk was still `running`); the next run shows
  `INTERRUPTED Copy` and `• TwinPane stopped before this operation finished;
  its outcome is unknown`.
- `history.json` inspected directly after the runs: records carry `op`,
  `status`, `started`, `finished`, `sources`, `dest`, `items`, `summary`,
  `files`/`bytes` and (for failures) `errors`.

## Not verified here
- rclone and 7-Zip are not installed, so remote operations were exercised

  of a live rclone run; the recording code path is the same.
- Retention was not exercised with more than a handful of real runs on the
  pty; pruning itself is covered by the unit tests (limit 1–3 with six runs).
