## Tests that were stale after the merge

Three `internal/ui` tests failed in CI from `b6b7930` onwards (they pass in a
sandbox without rclone, editors or 7-Zip, which is why the local runs were
green). Each asserted behaviour that an earlier feature had changed; the tests
were realigned, the application code was not touched.

- `TestCloudGatingAndErrorState` still listed `v` and `enter` among the keys
  that "must not act on a remote file". Since the read-only remote preview,
  both open the viewer, so the test now keeps the write keys in the refusal
  loop and asserts that `v` and `Enter` open a preview marked `READ-ONLY`,
  that it is flagged as remote, and that `Esc` closes it.
- `TestCloudCancelTransfer` read the cancellation from the status line, but a
  result is now a notification (`taskResult` clears the status). It asserts on
  `h.reported()` and `h.reportedLevel()` (`warn`), the same helpers the
  notification tests use.
- `TestCtrlOIgnoredWhileOverlayOwnsKeyboard` sent the literal `"esc"` through
  the raw helper in `app_test.go`, which built a three-rune burst that the
  viewer read as typeahead (`e` starts the editor). The helper now emits a real
  `tea.KeyEsc`, so `press(a, "esc")` closes instead of editing.

Reproduced locally by installing real rclone 1.75.2 and 7-Zip and putting
editors on `PATH`, which is the CI setup; all three pass there, and the whole
suite is green with `TWINPANE_REQUIRE_TOOLS=1`.
