    history entries; the user guide keeps master's task-screen and
    notification text and the branch's history section.
- Non-Git integration found and fixed after the merge:
  - `currentPrefs()` did not carry the retention limit, so any unrelated
    settings save (e.g. toggling hidden files) would have written
    `historySessions: 0` and reset the preference. It now includes
    `HistorySessions` from the store, and the history view's `+`/`-` saves the
    whole preference set instead of a two-field file.
  - The Settings screen gained an **Operation history → Runs kept** row
    (`rowHistorySessions`, 1–200 via `history.ClampLimit`, pruning at once);
    `applyPreferences` (used by `r` reset) also resets the store's limit.
  - The history view now owns every key while it is on screen: a stray `x`/`c`
    can no longer clear the task list or cancel a live task from it.
  - Two master tests assumed the old UI: `TestHistoryKeysStayOutOfDialogs`
    opened the folder prompt with `n` (now `F7`, since `n` opens the New menu)
    and `TestHelpMatchesBindings` expected every binding on one 80x60 screen
    (the help is taller now), so it scrolls and collects all pages.
